# 배포 런북 — PR 4: 조회 성능

마이그레이션: `063`. **PR 3(`061`, `062`) 적용 이후에만 진행한다.**

## 1. 사전 게이트

1. `063`은 `pg_trgm` 확장을 `extensions` 스키마에 설치한다. Supabase 프로젝트에서 확장 설치가
   허용되는지 확인한다.
2. GIN 인덱스 4개를 생성한다. 대상 테이블 크기에 따라 시간이 걸릴 수 있다. `themes`와
   `theme_stocks`의 행 수를 미리 확인하고, TLI 수집 잡이 돌지 않는 시간대에 적용한다.
3. 마이그레이션 전체가 `BEGIN`/`COMMIT`으로 감싸져 있어 실패 시 원자적으로 되돌아간다.
4. 클린 체크아웃에서 `tsc`, `eslint`, `vitest`, `next build` 통과

## 2. 적용 순서

1. 마이그레이션 `063` 적용
2. 검증된 커밋 배포

**앱 배포는 `063` 적용 이후여야 한다.** RPC가 없는 상태로 새 코드가 뜨면 랭킹/비교/변동
엔드포인트가 RPC 부재 오류를 반환한다.

## 3. 스모크 체크

- `/themes` 랭킹이 정상 렌더되고 서버 로그에 `load_theme_score_windows` 부재 오류가 없다
- `/api/tli/compare?ids=...` 응답에서:
  - `sparkline` 배열이 **과거 → 최신** 순서인지 확인 (역순 회귀 방지)
  - `warnings`에 유사도 로드 실패 메시지가 없는지 확인
- `/api/tli/changes?period=7d` 정상 응답
- 테마/종목 검색이 이전보다 느려지지 않았는지 확인 (trgm 인덱스 적용 효과)
- 테마 수가 1,000개를 넘어도 랭킹에서 누락되는 테마가 없는지 확인 (COR-016의 본래 목적)

## 4. 롤백

- 앱을 직전 검증 배포로 롤백하면 이전 쿼리 경로로 돌아간다
- RPC와 인덱스는 additive이므로 남겨둬도 무해하다. 굳이 제거해야 하면
  `DROP FUNCTION` / `DROP INDEX`를 개별 실행한다(확장은 남긴다).
