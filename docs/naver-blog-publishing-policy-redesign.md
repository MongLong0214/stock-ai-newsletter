# 네이버 블로그 자동 발행 — 정책 재설계안

> **상태**: Isaac 결정 대기. 이 문서는 판단 근거를 정리한 것이고 코드에 적용하지 않았다.
> **작성**: 2026-09-03 (계정 보호조치 2회 발생 당일)
> **전제**: 자동 발행은 현재 전면 중단 상태다. 이 문서는 "다시 켤지, 켠다면 어떻게"를 다룬다.

## 0. 반증된 전제부터

`naver-blog.yml` 주석은 이렇게 전제했다.

> 빈도 자체는 문제가 아니다 — 네이버 C-Rank는 꾸준한 발행을 활동성 신호로 보고
> 상위 블로그는 대부분 매일 쓴다. 위험한 것은 같은 템플릿의 반복이므로
> 5종 로테이션과 14일 테마 쿨다운으로 그쪽을 막는다.

**계정이 실제로 막혔으므로 이 전제는 반증됐다.** 어디가 틀렸는지 나누면:

| 전제 | 판정 | 근거 |
|---|---|---|
| "상위 블로그는 매일 쓴다" | **오적용** | 사실이지만 그건 **이력이 쌓인 블로그**다. 8/27 리브랜딩 직후의 신생 블로그에 적용할 수 없다 |
| "빈도 자체는 문제가 아니다" | **반증** | 신생 + 매일 + 100% 자동 + 100% 외부링크의 **조합**이 문제였다. 빈도는 그 조합의 핵심 변수다 |
| "5종 로테이션으로 템플릿 반복을 막는다" | **반증** | 아래 §4에 실측. 로테이션은 골격을 바꾸지 못했다 |

교훈: 안전장치를 **개별로** 평가했다. 네이버가 보는 것은 신호의 조합이다.

## 1. 냉각 기간 권고

### 권고: 자동화 전면 중단 14일 + 마지막 보호조치 해제로부터 최소 72시간은 어떤 자동 접근도 금지

| 구간 | 기간 | 허용 |
|---|---|---|
| 절대 침묵 | 해제 후 72시간 | 네이버 접근 0. 사람 로그인조차 최소화 |
| 사람 전용 | 14일까지 | 사람의 평소 사용만(로그인·열람·댓글). 자동화 0 |
| 재개 판정 | 14일 이후 | §5 조건 충족 시 Isaac이 판정 |

### 근거

1. **2회차가 해제 직후 발생했다.** 해제는 계정을 "정상"으로 돌리지만 네이버의 감시 상태를 끄지 않는다. 해제 직후 자동 접근은 감시 중인 계정에 재범 신호를 준다 — 실제로 그렇게 됐다. 72시간은 감시가 느슨해질 최소 시간에 대한 보수적 추정이다(**추정**, 네이버 비공개 정책).
2. **침묵만으로는 원인 신호가 사라지지 않는다.** 계정의 전체 이력이 "신생 + 100% 자동 + 매일 + 전 글 외부링크"다. 자동화를 멈추면 신호가 **늘지 않을** 뿐, 이미 쌓인 신호는 그대로다. 그래서 냉각 기간을 **사람의 실제 사용으로 채우는 것**이 침묵보다 낫다 — 사람 사용 이력이 자동화 비중을 희석한다.
3. **2회 발생은 누진 신호다.** 네이버 보호조치는 반복될수록 강한 제재(장기 이용제한·폐쇄)로 올라가는 구조로 알려져 있다(**일반 지식**). 3회차의 비용이 2회차와 같다고 가정할 근거가 없다. 14일은 "짧게 시도해 보고 안 되면 또"를 배제하기 위한 값이다.

### 이 기간에 반드시 확인할 것

`session-sync`의 키프얼라이브는 **매일 네이버에 접촉한다**(내가 어제 넣었다). 발행이 없는 날에도 세션을 살리려는 설계인데, **감시 중인 계정에서는 정확히 반대로 작동한다** — 발행 없이 접근만 늘린다. 재개 시 키프얼라이브 주기는 **발행 주기를 초과하지 않아야 한다**(§2와 함께 결정).

## 2. 재개 시 발행 빈도

### 권고: 주 2회. 단 재개 후 첫 4주는 주 1회로 시작해 단계적으로 올린다

| 단계 | 빈도 | 기간 | 조건 |
|---|---|---|---|
| 1 | 사람이 수동 1편 | 1주 | §5 재개 조건 충족 후 |
| 2 | 자동 주 1회 | 4주 | 1단계 무사고 |
| 3 | 자동 주 2회 | 유지 | 2단계 무사고 |

`WEEKLY_PUBLISH_LIMIT`은 7 → **3**으로 낮춘다(상한은 폭주 방지용이므로 목표치보다 1 여유).

### 근거

1. **자동 접촉을 71% 줄인다.** 매일(7회/주) → 주 2회. 문제가 빈도-조합이었으므로 가장 직접적인 레버다.
2. **C-Rank는 일관성을 보고 절대량을 보지 않는다.** 주 2회를 꾸준히 유지하는 것이 매일 쓰다 계정이 막혀 0이 되는 것보다 누적 신호가 강하다. 실제로 지금 8편에서 멈췄다.
3. **단계적 증가가 핵심이다.** 이번 실패의 형태는 0 → 매일로 즉시 점프였다. 신생 블로그가 갑자기 매일 쓰는 것 자체가 이상 신호다. 램프업은 그 점프를 없앤다.
4. **주 2회 = 월 8~9편**으로 SEO 목적에는 충분하다. 메모리 기준 이 프로젝트의 진짜 병목은 발행량이 아니라 백링크였다(트래픽 전략 전환). 발행량을 줄여도 전략 손실이 작다.

**불확실성**: 네이버가 어떤 빈도를 안전하다고 보는지는 비공개다. 주 2회는 "매일보다 확실히 낮고, 일관성을 유지할 수 있는 값"이라는 판단이며 **실측 근거는 없다.** 안전을 확인하는 방법은 §5의 관측뿐이다.

## 3. 외부 링크 정책

### 권고: 전 글 포함(100%) → **최대 50%**, 그리고 오글링크 카드를 기본에서 뺀다

| 항목 | 현재 | 권고 |
|---|---|---|
| 링크 포함 비율 | 100% (`outsideUrl` 필수) | 최대 50%, 링크 없는 유형 추가 |
| 링크 형태 | 오글링크 **카드**(마지막 컴포넌트 고정) | 문장 내 평문 링크. 카드는 사용하지 않음 |
| 출처 표기(데이터랩·KRX) | 유지 | **유지** — 이건 홍보가 아니라 출처다 |
| 방법론 링크 | 자사 도메인 | 유지하되 위 50% 안에서 계산 |

### 근거

1. **보호조치 사유에 "스팸메일 발송, 불법 게시물 작성"이 포함됐다.** 스팸 판정에서 가장 흔한 축이 홍보성 외부 링크의 반복이다. 우리는 **8편 전부**가 같은 도메인으로 나가는 링크를 가졌고, 그것도 시각적으로 가장 두드러지는 카드 형태로 글 마지막에 고정 배치했다. 이건 "매 글이 같은 사이트로 유도하는 구조"로 읽힌다.
2. **카드가 평문보다 나쁘다.** 카드는 썸네일·제목·도메인이 붙은 광고 유닛처럼 보인다. FORMAT-SPEC이 카드를 요구한 이유는 클릭률이었는데, 계정 위험과 교환할 가치가 아니다.
3. **링크 0개 유형이 필요하다.** 현재 5종 전부 링크를 갖는다. 용어·지표 해설처럼 자사 유도가 없는 정보성 글을 넣으면 비율이 자연히 내려가고, 블로그가 "홍보 채널"이 아니라 "정보 채널"로 보인다.

**결정 필요**: 이건 `FORMAT-SPEC.md`의 "CTA 필수"와 `checkFormat`의 `outsideUrl` 검증을 **완화**하는 변경이다. 안전장치 완화가 아니라 **스팸 신호 축소**지만, 규격 변경이므로 Isaac 승인 없이 적용하지 않았다.

## 4. 템플릿 다양성 — 현재 로테이션은 작동하지 않는다

### 실측 (내가 오늘 측정한 값)

**제목**: 발행된 8편 중 6편이 **동일한 문장 틀**이다.

```
2차전지  관련주 TOP 8 — 정점 단계, 점수 68점 (2026.08)
아이폰    관련주 TOP 8 — 정점 단계, 점수 70점 (2026.08)
스마트폰  관련주 TOP 8 — 정점 단계, 점수 69점 (2026.08)
건강기능식품 관련주 TOP 8 — 정점 단계, 점수 70점 (2026.08)
제습기    관련주 TOP 8 — 정점 단계, 점수 71점 (2026.08)
면세점    관련주 TOP 8 — 정점 단계, 점수 68점 (2026.08)
```

테마명과 두 자리 숫자만 바뀐다. **"TOP 8"과 "정점 단계"는 6편 전부 동일하다.**
FORMAT-SPEC은 제목 형태 A/B/C 세 개를 제시했지만 코드가 A로 고정했다(`composeTitle`).

**본문 골격**: 서로 다른 테마 3회 실행의 발행 전 검증 로그가 **완전히 같은 수치**다.

```
아이폰 (로컬)  발행 전 검증 통과 — 인용구 4개 · 볼드 19회 · 색상 4개 · 이미지 5장
영화   (로컬)  발행 전 검증 통과 — 인용구 4개 · 볼드 19회 · 색상 4개 · 이미지 5장
영화   (CI)    발행 전 검증 통과 — 인용구 4개 · 볼드 19회 · 색상 4개 · 이미지 5장
```

본문 길이도 아이폰 1,834자 / 영화 1,828자 — **6자 차이**. 제목 39자 / 38자.
인용구 소제목은 4개가 문구까지 고정이다(`점수 현황` / `점수를 만든 네 가지 요소` / `관련종목 N개` / `정리`).

즉 **로테이션은 "어떤 데이터를 넣을지"만 바꾸고 "어떻게 생긴 글인지"는 바꾸지 않았다.** 5종이 있어도 theme 유형이 대부분을 차지하면 실제 노출되는 골격은 하나다.

### 권고 — 관측 가능한 다양성

| 축 | 현재 | 권고 |
|---|---|---|
| 제목 틀 | A 고정 | A/B/C 순환 + "TOP N"·단계명 상수 제거 |
| 인용구 | 4개, 문구 고정 | 3~5개 변동, 소제목 문구 2~3안 중 선택 |
| 이미지 수 | 사실상 5 고정 | 4~6 변동 |
| 도입부 | 수치 제시 1종 | 질문형·정의형·수치형 순환 |
| 블록 순서 | 완전 고정 | 의미가 허용하는 범위에서 2~3개 배열 |
| 본문 길이 | 1,83x자 수렴 | 목표 밴드를 넓혀 편차 허용 |

**검증 방법**: 연속 초안 N개를 생성해 위 축들의 값이 **최소 3개 축에서 달라야** 통과하는 테스트를 추가한다. 지금은 "규격을 만족하는가"만 보고 "서로 다른가"는 보지 않는다. 이게 로테이션이 무력했던 이유다.

**한계 (정직하게)**: 템플릿 기반 생성의 다양성에는 천장이 있다. 위 조치는 "기계가 찍어낸 티"를 줄이지만 없애지 못한다. 진짜 다양성은 문장 생성을 LLM에 맡길 때 나오는데, 그건 YMYL 결정성(같은 데이터 → 같은 서술)과 충돌한다. **이 교환은 Isaac이 결정할 사항**이며, 나는 §6을 더 권한다.

## 5. 재개 판정 기준 (관측 가능한 조건)

**전부 충족해야 하고, 판정은 Isaac이 한다. 코드가 자동 재개하지 않는다.**

| # | 조건 | 확인 방법 |
|---|---|---|
| 1 | 마지막 보호조치 해제 후 14일 경과 | 날짜 |
| 2 | 그 기간 사람 로그인에서 보호조치·캡차·추가인증 **0회** | 사람이 평소처럼 로그인해 확인 |
| 3 | 기존 8편 중 삭제·블라인드 **0건** | 블로그에서 목록 확인 |
| 4 | 블로그가 네이버 검색에 정상 노출 | 사람이 검색으로 확인 |
| 5 | 이용제한 안내 **없음** | 로그인 후 알림·고객센터 확인 |
| 6 | §2 램프업 계획과 §3 링크 정책이 코드에 반영됨 | 코드 리뷰 |
| 7 | 계정 상태 감지기가 동작함 | Task 2 구현·테스트 통과 (완료) |

**재개 순서** — 각 단계 사이의 관찰을 건너뛰지 않는다.

```
1) 사람이 수동으로 1편 발행          → 48시간 관찰
2) dry-run 1회 (사람이 화면 확인)     → 48시간 관찰
3) 자동 주 1회, 4주                  → 무사고 확인
4) 자동 주 2회
```

어느 단계에서든 보호조치·캡차가 재발하면 **즉시 전면 중단하고 §1로 돌아간다.** 3회차는 2회차보다 비싸다.

## 6. 자동 발행을 접는 선택지 (진지한 검토)

### 대안 A — 완전 수동

| | |
|---|---|
| **장점** | 계정 위험 사실상 0. 사람 행동 패턴이 C-Rank에 유리. 문체·구조 다양성이 자연히 확보됨. YMYL 신뢰도에 유리 |
| **단점** | 편당 30~60분. 지속성이 사람 의지에 의존. 데이터 최신성 하락 |

### 대안 B — 초안 자동 + 발행 수동 (**권고**)

파이프라인이 초안·이미지·캡션까지 **로컬 파일로만** 만들고, 네이버에는 사람이 직접 붙여넣어 발행한다. 네이버 자동 접근이 **0**이 된다.

| | |
|---|---|
| **장점** | 계정 위험 제거(자동 접근 0). 자동화 가치의 대부분(데이터 수집·수치 검증·이미지 캡처·초안 작성)을 그대로 유지. 편당 사람 시간 5~10분. 사람이 매번 보므로 품질·다양성 통제 가능 |
| **단점** | 발행이 사람 일정에 묶임. 완전 무인은 포기 |

### 왜 B를 권하는가

1. **위험과 가치가 비대칭이다.** 계정이 폐쇄되면 8편과 도메인 신뢰가 함께 사라지고 복구가 불가능에 가깝다. 반면 자동 발행이 절약하는 것은 **편당 5~10분**이다(초안·이미지는 이미 자동이므로 남는 건 붙여넣기와 확인). 이 교환은 성립하지 않는다.
2. **전략적 가치가 낮아졌다.** 이 프로젝트는 이미 블로그 양산을 중단하고 테마·AI 검색으로 축을 옮겼고, 진짜 병목은 백링크로 판단했다. 네이버 자동 발행은 그 전략의 핵심이 아니다.
3. **이미 만든 것을 버리지 않는다.** 위험한 부분은 `publish.ts`(네이버 접근)뿐이다. `make-draft`·`capture-images`·`format`·`compose-*`·검증 로직은 그대로 쓴다. 오늘 실측으로 초안·캡처·검증 전 구간이 정상 동작함을 확인했다(`인용구 4 · 볼드 19 · 색상 4 · 이미지 5`, 검증 통과).
4. **되돌릴 수 있다.** B로 몇 주 운영해 계정이 안정되고 사람 사용 이력이 쌓인 뒤, 원하면 §5 절차로 자동화를 다시 검토할 수 있다. 반대 방향(폐쇄 후 복구)은 되돌릴 수 없다.

### 권고 요약

**지금 결정할 것은 "자동 발행을 언제 켜냐"가 아니라 "켜야 하는가"다.** B를 기본으로 두고, §1~5는 나중에 자동화를 재검토할 때의 조건으로 보관하는 것을 권한다.
